- **상태**: Draft — 전략 확정, 실행 준비 中 (개발 착수 前 단계)
- **작성일**: 2026-08-20 (최종 수정: 대상 지역·비즈니스 모델·제휴 우선순위 확정 반영)
- **문서 목적**: "온라인 임장" 서비스의 방향성과 요구사항을 확정하기 위한 1차 논의 초안. 아래 내용은 제안이며, 특히 "확인 필요 사항" 섹션은 반드시 팀/대표 확인 후 확정 필요.

**이번 라운드 확정 사항**
- ✅ MVP 타겟 매물 유형: **아파트 + 오피스텔** (데이터 스키마·3D 매스·시세비교 로직·사용자 의도가 유사해 병행 개발이 효율적). 상가/토지/단독다가구는 결합도가 낮아 P2 별도 트랙.
- ✅ 차별화 전략: (1) 미도식화된 데이터의 시각화, (2) **부동산업체 데이터/매물 제휴** — 업체가 독점 매물·정보를 제공하고 PropScope 플랫폼 안에서 해당 매물 전용 에이전트로 노출 (화이트라벨 SaaS 아님, 데이터 소스 제휴 모델).
- ✅ 대상 지역: **수도권 우선** (서울 일부로 파일럿 → 수도권 전역 확대). 전국 확장은 현재 로드맵 범위 밖, 수도권 검증 후 재검토.
- ✅ 비즈니스 모델: **의도적으로 보류**. MVP는 수익모델 없이 제품 가치 검증에 집중하고, 수익화는 별도 트랙에서 추후 결정.
- ✅ 제휴(6.6 제휴 매물 에이전트): **후순위로 보류**. P1에서 진행하지 않고, 제품 핵심 경험이 검증된 이후 별도 BD 트랙에서 재개.

## 1. 배경 및 문제 정의

부동산 임장(현장 답사)은 다음과 같은 비효율을 가진다.

- **시간·거리 비용**: 후보 매물마다 직접 방문해야 하며, 이동 시간이 의사결정 속도를 늦춘다.
- **정보 파편화**: 시세(국토부 실거래가), 건축물대장, 등기 정보, 학군, 교통, 주변 상권 정보가 각각 다른 사이트/앱에 흩어져 있어 종합 판단이 어렵다.
- **비전문가의 정보 해석 부담**: 실거래가 그래프, 공실률, 건축물대장 용어 등은 일반 사용자가 스스로 해석하기 어렵다.
- **1차 필터링 수단 부재**: 다수 후보지를 압축하기 전 온라인에서 "가볼 만한 곳"을 걸러낼 도구가 마땅치 않다.

→ **가설**: AI 챗봇이 안내하는 3D 공간 탐색 + 데이터 시각화를 결합하면, 실제 임장 전 온라인에서 1차 스크리닝을 완결할 수 있는 경험을 만들 수 있다.

## 2. 제품 비전

> "발로 뛰기 전에, 화면 안에서 먼저 임장한다."

사용자가 챗봇에게 자연어로 조건을 말하면(예: "강남역 도보 10분 이내, 20평대, 매매 12억 이하 아파트 보여줘"), AI가 후보 건물을 추리고 3D 뷰로 건물과 주변을 보여주며, 시세 추이·입주 현황·생활 인프라를 함께 설명해주는 서비스.

## 3. 목표 및 성공 지표 (초안 — 확정 필요)

| 구분 | 지표 (제안) | 비고 |
|---|---|---|
| 활성化 | 첫 세션에서 3D 뷰 진입 + 챗봇 3턴 이상 대화 완료율 | 온보딩 성공 기준 |
| 리텐션 | 관심 매물 저장 후 7일 내 재방문율 | 임장은 반복 탐색 행위이므로 중요 |
| 핵심 가치 검증 | "실제 방문 없이 후보군을 N개 → M개로 좁혔다"는 사용자 응답 비율 | 설문/인터뷰 기반 |
| 데이터 신뢰도 | 실거래가·건축물대장 등 표시 정보의 최신성(공식 소스 대비 지연일수) | 데이터 파이프라인 SLA와 직결 |

비즈니스 모델은 의도적으로 보류하기로 했으므로, MVP 단계의 지표는 **수익이 아닌 제품 가치 검증에만 집중**한다 (위 4개 지표 그대로 사용). 수익 관련 지표(전환율, ARPU 등)는 비즈니스 모델이 정해지는 시점에 별도로 추가.

## 4. 타겟 사용자 (가설 페르소나)

1. **실수요 매수/전세 희망자** — 후보지 5~10곳을 온라인에서 먼저 좁히고 싶은 2030~4050 개인.
2. **바쁜 투자자/임장 대행 의뢰자** — 지역 시세·추이를 빠르게 스캔하고 싶은 사용자.
3. **부동산업체(데이터 파트너)** — *제품의 사용자가 아니라 데이터 공급자.* 독점 매물·정보를 제공하고, 그 대가로 자사 매물이 PropScope 안에서 전용 에이전트로 노출됨. (공인중개사가 직접 로그인해 쓰는 B2B 툴이 아님 — 필요해지면 별도 검토)

MVP는 **1번 페르소나** 중심 B2C 경험에 집중. 3번은 사용자가 아닌 **데이터 공급 채널**로 6.6/8에 별도 반영.

## 5. 핵심 사용자 여정 (E2E 시나리오, 초안)

1. 사용자가 챗봇에 지역/조건을 자연어로 입력
2. AI가 조건에 맞는 후보 건물 리스트 + 지도 상 위치 제시
3. 사용자가 건물 하나 선택 → **3D 뷰**로 건물 외관 + 주변 블록 진입
4. 3D 뷰 내에서 클릭 시 옆에 **주변 시세 비교 패널**(반경 500m 등) 표시
5. 챗봇에게 "여기 요즘 전세가 오르는 추세야?" 등 질문 → **입주현황/가격 추이 차트**로 답변
6. 사용자가 여러 건물을 "관심 목록"에 저장 → 비교표로 나란히 비교
7. (선택) 실제 임장 방문 예약/중개사 연결로 전환

이 여정 중 **3~5번이 제품의 핵심 차별화 지점**이며 MVP의 중심이 되어야 한다.

## 6. 기능 요구사항

### 6.1 AI 임장 챗봇 (LLM 어시스턴트)
- 자연어 조건 파싱 → 매물/건물 검색 필터로 변환 (지역, 예산, 평형, 매매/전세/월세, 준공연도 등)
- 3D 뷰·차트와 연동된 **컨텍스트형 Q&A** (현재 보고 있는 건물 기준으로 응답)
- 데이터 기반 요약 생성 (예: "최근 6개월 실거래가 3건 평균 OO억, 전분기 대비 +5%")
- **환각 방지**: 가격·시세 등 정량 데이터는 LLM이 생성하지 않고, 반드시 조회된 원본 데이터를 함수 호출(tool use)로 가져와 인용하는 구조로 설계 (RAG/도구 호출, 프롬프트로 숫자 생성 금지)
- 대화 히스토리 기반 추천 개선 (세션 내 최소, 로그인 시 영구 저장)

### 6.2 3D 건물/단지 뷰어
- 건물 외관 3D 렌더링 (단지 배치도 수준 우선, 개별 세대 내부는 후순위)
- 주변 블록 컨텍스트(인접 건물, 도로, 지형) 포함한 미니 도시 뷰
- 카메라 이동(회전/줌/이동), 클릭 시 정보 패널 오픈
- 로드뷰/실사 이미지 연동(카카오맵·네이버 로드뷰 API 등)으로 3D 매스 모델의 몰입감 보완

### 6.3 주변 시세 비교
- 반경 기반(예: 300m/500m/1km) 유사 평형 실거래가 비교
- 매매/전세/월세 탭 전환
- 지도 위 히트맵 또는 마커 클러스터로 시세 분포 시각화
- 동일 단지 vs 인근 단지 비교 뷰

### 6.4 입주현황 및 추이 차트
- 실거래가 시계열 추이 (라인 차트)
- 거래량 추이 (전입/전출 세대수 또는 실거래 건수로 proxy — 아래 리스크 참조)
- 전세가율, 매매-전세 갭 추이
- (상업용 건물의 경우) 공실률 추이 — 데이터 확보 방안 별도 필요

### 6.5 부가 정보 레이어 (P1~P2)
- 건축물대장 요약 (준공연도, 구조, 층수, 용도)
- 교통(지하철역 거리, 버스 노선), 학군, 생활 인프라(마트/병원/공원)
- 일조/소음 등 환경 요소 (P2, 데이터 확보 난이도 높음)
- 관심 매물 비교표, 공유 링크

### 6.6 제휴 매물 에이전트 (P2 이후, 보류 — 데이터 파트너십 기반)
- **결정**: 제휴는 BD/계약이 선행되어야 하는 별도 트랙이라 제품 핵심 경험(P0/P1) 검증보다 뒤로 미룬다. 아래는 재개 시 참고할 설계 방향.
- 제휴 부동산업체가 제공한 **독점 매물/정보**를 별도 데이터 소스로 수집
- 해당 매물 상세 화면에서 챗봇이 "이 매물은 OO공인중개사 제휴 매물" 형태로 출처를 명시하고, 업체가 제공한 추가 정보(내부 사진, 특이사항 등)로 답변을 보강
- 공개 실거래가 기반 일반 매물과 **동일한 3D 뷰/시세비교/차트 UI**를 그대로 사용 — 제휴는 데이터 소스 레이어에서만 추가되고 UI/UX는 분기하지 않음
- 재개 시: 파일럿 업체 1~2곳 확보 → 검증 (데이터 제공 계약, 정보 정확성 책임 소재는 BD/법무 트랙에서 별도 논의 필요)

## 7. 비기능 요구사항

- **성능**: 3D 뷰 초기 로딩 3초 이내(모바일 4G 기준), 저사양 기기 폴백(2D 지도+사진으로 대체) 필수
- **데이터 신뢰성**: 실거래가 등 정량 데이터는 출처·기준일 명시, 캐시 정책과 갱신 주기 SLA 정의
- **모바일 대응**: 반응형 + 3D 뷰의 모바일 GPU 성능 고려한 LOD(Level of Detail) 전략
- **개인정보/법적 이슈**: 등기부등본 등 개인정보 포함 데이터는 원본 스크래핑 금지, 공식 유료 API/제휴 경유. 위치정보사업자 신고 등 규제 검토
- **접근성**: 3D 뷰 미지원 환경(구형 브라우저, 저사양)에서도 핵심 정보(시세, 차트)는 2D로 이용 가능해야 함
- **확장성**: 지역 확장(수도권→전국) 시 데이터 파이프라인이 지역별 하드코딩 없이 확장 가능한 구조

## 8. 데이터 및 외부 연동 (국내 서비스 기준 제안)

| 데이터 | 소스 후보 | 비고 |
|---|---|---|
| 아파트/오피스텔/단독다가구/토지 실거래가 | 국토교통부 실거래가 공개시스템 (공공데이터포털 Open API) | 무료, 신고 지연(최대 30일) 존재 |
| 건축물대장 | 국토교통부/세움터, 공공데이터포털 | 무료 |
| 3D 지형·건물 모델 | 국토지리정보원 브이월드(V-World) 3D API | 국내 무료, 커버리지·정밀도 확인 필요 |
| 지도/로드뷰/지오코딩 | 카카오맵 API, 네이버 지도 API | 트래픽 과금 정책 확인 필요 |
| 상권/편의시설 | 소상공인시장진흥공단 상권정보 | 무료 |
| 공실률(상업용) | 부동산원 R-ONE, 민간 리서치(젠스타메이트 등) | 대부분 유료·제휴 필요, MVP 제외 검토 |
| 등기 정보 | 대법원 인터넷등기소 | 원칙적으로 스크래핑 불가, 유료 API 대행사 검토 |
| 학군 | 학교알리미 | 무료 |
| **제휴 부동산업체 매물/정보** | 개별 업체와의 데이터 제휴 계약 (6.6) | 공개 API 아님. 파일럿 업체 발굴·계약이 선행 조건. 데이터 포맷 표준화 필요 |
| LLM | Anthropic Claude 등 | 도구 호출(tool use)로 정량 데이터 조회 구조 필요 |

**리스크**: 입주현황/공실률은 한국에 정제된 공개 데이터가 부족함. MVP에서는 "실거래 건수·전입세대 변화" 등 proxy 지표로 대체하고, 정확한 공실률은 후속 단계에서 유료 데이터 제휴로 보강하는 것을 제안.

|---|---|---|---|
| **MapLibre GL JS** <span style="font-size:12px;">(구 후보: Mapbox GL JS → 스파이크 후 교체)</span> | 지도 기반 3D, 실제 지리좌표와 자연스러운 결합, 국내 지도 데이터와 병행 가능. **오픈소스·토큰 비용 없음** (Mapbox GL JS는 v2부터 독점 라이선스라 대체) | 개별 건물 디테일 표현엔 한계, 번들 크기 gzip 218KB(스파이크 실측) — 4G 로딩 목표 대비 유의 필요 | 주변 블록/도시 컨텍스트 뷰 |
| **CesiumJS** | 대규모 지형·3D Tiles 표준 지원, 포토리얼리스틱 타일 연동 가능 | 러닝커브 높음, 무거움, Cesium ion 토큰 필요(벤더 종속). 이번 스파이크에서 미실험 — 광역 지형이 필수 요건이 아니라 우선순위 낮춤 | 광역 지형+도시 스케일 뷰 (필요시 재검토) |
| **Three.js / Babylon.js** | 커스텀 건물 모델(자체 모델링/스캔) 표현 자유도 최고. 스파이크에서 OrbitControls+매스 모델+클릭 연동 확인 (번들 gzip 124KB) | 지리좌표 연동, 대규모 씬 관리를 직접 구현해야 함 | 개별 건물 상세 뷰, 인터랙션 |
| **VWorld 3D (국토지리정보원)** | 국내 건물 3D 데이터 무료 제공 | 커버리지·갱신 주기·상업적 활용 조건 확인 필요. 스파이크에서 미검증(API 키 필요) | 국내 건물 매스 모델 소스 |

**확정된 구조**: (1) 도시/블록 스케일은 **MapLibre GL JS**로 지리 컨텍스트 처리, (2) 선택된 개별 건물의 상세 뷰는 **Three.js** 커스텀 씬으로 전환하는 하이브리드 구조. 스파이크로 전환 메커니즘 자체는 검증됨 — 남은 리스크는 실 데이터 연동과 실기기 성능 (아래 참고).

## 10. MVP 범위 제안 (P0/P1/P2)

**P0 (MVP 필수)**
- 매물 유형: **아파트 + 오피스텔** (확정 — 결합도 높아 병행 개발)
- 챗봇: 자연어 조건 → 검색 필터 변환, 결과에 대한 도구 호출 기반 답변
- 3D 뷰: 선택 지역의 블록 단위 3D 매스 뷰 (개별 건물 디테일 모델 X, 우선 매스/지도 3D)
- 주변 시세 비교: 실거래가 기반 반경 비교
- 가격 추이 차트: 라인 차트 1종
- 대상 지역: **수도권** 내 파일럿 자치구 1~2곳 (서울 우선 착수, 예: 강남/마포 등 — 구체 지역은 확인 필요)

**P1**
- 관심 매물 저장/비교표
- 건축물대장 요약 정보
- 로드뷰 연동
- 대상 지역 확대: **수도권 전역**

**P2 (후속)**
- 매물 유형 확장: **상가/토지/단독다가구** (결합도 낮아 별도 트랙 — 가격비교 로직·UX 새로 설계 필요)
- 개별 건물 상세 3D 모델(내부 평면 포함)
- 공실률(상업용) 데이터
- 일조/소음 등 환경 데이터
- **제휴 매물 에이전트** (6.6) — 현재 보류, 제품 핵심 경험 검증 후 BD 트랙에서 재개

**로드맵 범위 밖 (별도 재검토)**
- 전국 서비스 확장 — 수도권 검증 후 재검토
- 수익모델(광고/구독/제휴 수수료 등) 구현 — 비즈니스 모델 확정 이후

## 11. 로드맵 (제안, 주 단위는 팀 리소스 확정 후 조정)

| 단계 | 내용 | 산출물 |
|---|---|---|
| Phase 0 | 전략/요구사항 확정, 데이터 소스 계약·PoC, 3D 스택 기술 스파이크 | 확정 PRD, 기술 검증 리포트 |
| Phase 1 (MVP) | P0 기능 개발, 수도권 내 1~2개 자치구 데이터 파이프라인 구축 | 내부 데모 가능한 MVP |
| Phase 2 | P1 기능, 수도권 전역으로 지역 확장, 사용자 테스트 | 비공개 베타 |
| Phase 3 | P2 기능(매물 유형 확장, 제휴 매물 에이전트 재개) | 공개 출시 준비 |

전국 확장과 수익모델 도입은 위 로드맵에 포함하지 않음 — 수도권 검증 및 제품 가치 확인 이후 별도로 논의.

## 12. 리스크 및 확인 필요 사항 (반드시 논의 필요)

**전략 관련**
1. ~~타겟 매물 유형~~ → ✅ **확정**: 아파트+오피스텔 (P0), 상가/토지/단독다가구는 P2 별도 트랙
2. ~~대상 지역~~ → ✅ **확정**: 수도권 우선 (서울 파일럿 → 수도권 전역). 전국은 로드맵 범위 밖, 추후 재검토
3. ~~비즈니스 모델~~ → ✅ **확정(의도적 보류)**: MVP는 수익모델 없이 제품 가치 검증에 집중, 수익화는 추후 별도 결정
4. ~~경쟁 서비스와의 차별화~~ → ✅ **확정**: (1) 미도식화 데이터 시각화, (2) 부동산업체 데이터/매물 제휴 기반 전용 에이전트. 단, 직방/호갱노노/네이버부동산 대비 실제 방문 대체 효과는 초기 사용자 검증 여전히 필요
5. ~~제휴 대상·조건~~ → ✅ **확정(보류)**: 제휴(6.6) 자체를 P2 이후로 미루기로 결정. 대상 업체·조건 논의는 제품 핵심 경험 검증 후 BD 트랙에서 재개

**데이터/기술 관련**
6. 입주현황·공실률 데이터의 국내 공개 데이터 한계 → proxy 지표 채택 여부 결정
7. 개별 건물 3D 모델을 자체 제작(모델링/스캔)할지, VWorld 등 공개 데이터로 대체할지 — 비용·정밀도 트레이드오프
8. 등기부등본 등 개인정보 포함 데이터 사용 범위와 법적 검토(위치정보법, 개인정보보호법)
9. LLM 응답의 정량 데이터 환각 방지 아키텍처(도구 호출 강제) 설계 검토
10. 제휴 매물 데이터의 포맷·신뢰성 검증 파이프라인 — 업체마다 데이터 품질이 다를 가능성
