PORTFOLIO CASE STUDY

무엇을 하지 않을지부터
정했다

PropScope는 AI 챗봇과 3D 뷰어로 "온라인 임장"을 구현하는 개인 포트폴리오 프로젝트다. 예산도, 팀도, 개발 가능한 PC조차 없는 상태에서 시작했다 — 그래서 첫 작업은 코드가 아니라, 범위를 계속 좁혀나가는 일련의 판단이었다.

Field Log · 01–05

다섯 번의 판단

넓은 아이디어를 실행 가능한 범위로 좁힌 순서. 각 항목은 "무엇을 검토했는가"가 아니라 "무엇을 하지 않기로 했는가"로 끝난다.

01문제 정의

기존 서비스들의 공백은 "이해를 돕는 경험"이었다

네이버부동산은 매물 데이터베이스가, 호갱노노는 실거래가 시각화가, 직방은 실사 이미지가 강하다. 그런데 이 셋을 하나의 흐름으로 묶어 "왜 이 가격인지, 이 동네가 어떤지"를 설명해주는 곳은 없었다.

서비스강점공백
호갱노노실거래가 시각화정적 차트, 공간 경험 없음
직방로드뷰·실사 이미지시세·AI와 통합 안 됨
네이버부동산매물 DB 규모"설명"이 없음, 리스트뿐
Decision 시각화(호갱노노) + 대화형 안내(직방의 초기 시도) + 3D 공간감(전무)을 한 경험으로 묶는다. 매물을 더 모으는 경쟁은 하지 않는다.
02범위 압축

매물 유형은 "결합도"로 골랐다

아파트, 오피스텔, 상가, 토지를 전부 다루고 싶었지만, 데이터 스키마·3D 매스 모델링·시세비교 로직·사용자 의도 네 축으로 결합도를 뜯어보니 결과가 갈렸다. 아파트-오피스텔은 네 축 모두에서 겹치고, 상가·토지는 가격 단위부터(평당가 vs 임대수익률) 완전히 달랐다.

Decision 아파트+오피스텔만 먼저 만든다. 결합도가 낮은 상가/토지는 별도 트랙으로 미룬다 — "더 넓게"가 아니라 "결합도 높은 것부터".
03차별화 재정의

"부동산업체 협업"은 B2B 제품이 아니라 데이터 채널이었다

처음엔 "부동산업체와 협업하는 에이전트"를 세 번째 사용자 페르소나로 뒀다. 그런데 실제로 필요한 건 업체가 로그인해서 쓰는 툴이 아니라, 독점 매물·정보를 받아 서비스 안에서 노출하는 데이터 공급 채널이었다. 페르소나를 다시 썼다.

Decision 부동산업체 = 사용자가 아니라 데이터 파트너. 화이트라벨 SaaS를 만들지 않는다.
04의도적 보류

지역은 정하고, 돈 버는 방법은 정하지 않았다

대상 지역은 서울 파일럿 → 수도권 전역으로 확정했다 — 전국은 지금 다룰 규모가 아니다. 반대로 비즈니스 모델과 업체 제휴는 의도적으로 결정을 미뤘다. 둘 다 별도의 BD/계약 트랙이 필요한데, 검증되지 않은 제품 위에 그 트랙을 얹는 건 순서가 잘못됐다고 판단했다.

Decision 수도권 우선 확정 / 비즈니스 모델·제휴는 P2 이후로 보류. MVP 지표도 수익이 아니라 제품 가치 검증에만 맞춘다.
05기술 리스크 제거

스파이크로 Mapbox를 MapLibre로 바꿨다

"지도 기반 3D + 커스텀 건물 씬"이라는 하이브리드 구조가 실제로 이어지는지, 무료 스택만으로 로컬 PoC를 만들어 확인했다. 외부 타일 서버 없이 합성 데이터로 압출 렌더링과 화면 전환까지 실제 브라우저에서 검증했고, 그 과정에서 Mapbox GL JS(유료 토큰 필요)를 오픈소스 호환 포크인 MapLibre GL JS로 바꾸는 게 낫다는 결론을 얻었다.

Decision 지도 레이어는 MapLibre GL JS, 상세 뷰는 Three.js. 실 API 연동(브이월드·카카오·네이버)은 검증 못 함 — 다음 단계로 명시적으로 남겨둔다.
Sizing Check

퍼미 추정으로 방향만 확인

투자 유치용 숫자가 아니라, "이 범위가 말이 되는가"를 스스로 점검하기 위한 하향식 추정. 가정은 전부 명시했고, 실제 의사결정에는 공식 통계로 재계산이 필요하다.

TAM
~84만 가구/년
SAM
~44만 가구/년
SOM
~600–1,000가구 (1차 파일럿)

수도권 인구 2,600만 → 가구 환산 → 연간 이사율 11% → 아파트/오피스텔 비중 65% = TAM. 여기에 온라인 앱 이용률·실수요 비중을 곱해 SAM, 파일럿 자치구 비중과 초기 침투율을 곱해 SOM을 냈다. 전체 가정과 계산 과정은 PRD 부록 A 참고.

Current State

지금 증명된 것 / 아직 증명 안 된 것

포트폴리오 리뷰어가 가장 궁금해할 질문에 대한 솔직한 답.

증명됨

전략 문서 + 동작하는 PoC

  • 결정의 근거가 문서화된 PRD — 5개 전략 항목 전부 확정, 부록에 경쟁분석·시장추정 포함
  • 실제 브라우저에서 렌더링되는 3D PoC — 지도뷰 ↔ 상세뷰 전환까지 end-to-end
  • 기술 스택 재선정 판단 — 실측 근거(번들 크기)를 남긴 채로
아직 안 됨

실 데이터, 실 사용자

  • 브이월드·카카오·네이버 API 실연동 (개발 환경 제약으로 보류)
  • 실사용자 인터뷰로 시장 추정치 검증
  • 비즈니스 모델·업체 제휴 — 의도적으로 아직 결정 안 함
Takeaway

제약은 생략이 아니라 순서였다

리소스가 없다고 전략을 빼지 않았다. 대신 "지금 결정할 것"과 "지금 결정하지 않을 것"을 나눴다 — 매물 유형은 결합도로, 지역은 검증 가능한 크기로, 비즈니스 모델은 순서가 아니라서 미뤘다. 다음 사람이 이어받아도 왜 이렇게 좁혔는지 그대로 읽을 수 있게 남기는 것, 그게 이 프로젝트에서 가장 공들인 부분이다.
